# 演示录屏脚本

最终录屏目标：3-5 分钟，覆盖所有评分核心功能，节奏紧凑无冗余。
本脚本在开发过程中持续更新——每完成一个阶段，就验证对应路径是否能丝滑演示。

---

## 录屏前置准备

### 设备与环境
- 测试机：[待填，建议 Android 12 或 13 真机；模拟器作为备份]
- 系统语言：中文（演示文案为中文）
- 录屏工具：Android Studio 内置录屏 / scrcpy / 系统自带录屏
- 屏幕分辨率：保持设备原生分辨率，不要拉伸
- 网络：开启，但项目主线不依赖网络（除服务端拓展外）

### Mock 演示数据（必须提前准备）
mock_files.json 至少包含以下结构，确保演示路径所有节点都有数据可用：

```
根目录/
├── 文档/                    （文件夹，用于演示进入和移动）
│   ├── 项目说明.txt         （含中英文混排+多段落，用于演示 TXT 分页边界）
│   └── 备忘.txt             （短文本 < 1KB，演示边界）
├── 视频/                    （文件夹）
│   └── 演示片段.mp4         （< 5MB，演示系统播放器拉起）
├── 图片/                    （文件夹，演示筛选 Tab）
│   ├── photo1.jpg
│   ├── photo2.jpg
│   └── photo3.jpg
├── 音频/                    （文件夹）
│   └── audio1.mp3
└── 云收藏                   （置顶文件夹，演示 is_pinned 字段）
```

### 演示前 60 秒 checklist
- [ ] App 已重装到最新 APK
- [ ] Mock 数据已正确初始化（首次启动后检查）
- [ ] 剪贴板已清空（避免误识别上次的 token）
- [ ] 系统播放器存在（VLC 或系统自带）
- [ ] 录屏分辨率、帧率确认
- [ ] 静音模式开启，避免提示音干扰
- [ ] 通知栏清理，避免演示中弹出无关通知

## 录屏失败兜底路径

如果某个环节录屏时崩溃或异常，按优先级砍：

| 优先级 | 模块 | 砍了的影响 |
|---|---|---|
| 高（不能砍）| 网盘+文件 Tab、TXT 阅读、视频播放、上传、分享+剪贴板 | 主线丢分 |
| 中 | 多文件分享、置顶文件夹、筛选 Tab | 加分项丢分 |
| 低 | 类型筛选演示、排序演示 | 几乎不丢分 |

## 旁白文案要点（最终录屏时同步念）

- **不要**：照着代码细节念（评委不需要听 API 名）
- **要**：讲"为什么"和"亮点"
- 关键词出现频率（每个至少出现一次）：
  - "数据从 Room 流式更新"
  - "FileProvider 生成 content URI"
  - "基于测量的分页"
  - "分享快照表"
  - "剪贴板在 ON_RESUME 时识别"
  - "事务保证原子性"
